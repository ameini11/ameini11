# One-time setup

Both cards are generated by Actions in this repo. Neither needs Vercel or any
third-party hosting — the only secret involved stays in this repo's settings.

## 1. Create the PAT

The default `GITHUB_TOKEN` that Actions hands a workflow cannot see your private
repositories, and it acts as `github-actions[bot]` rather than as you. So both
workflows need a token that belongs to *you*.

Create a **classic** PAT at <https://github.com/settings/tokens> with scopes:

| scope       | needed for                                            |
|-------------|-------------------------------------------------------|
| `repo`      | reading private repos + cloning them for indepth stats |
| `read:user` | reading the contribution calendar                      |
| `read:org`  | private repos owned by orgs you belong to (optional)   |

Fine-grained PATs also work but are fussier here: indepth language analysis
clones every repo, so the token needs Contents:read on *all* of them.

Add it at **Settings → Secrets and variables → Actions → New repository secret**:

- Name: `PROFILE_TOKEN`
- Value: the token

## 2. Show private contributions on the profile

Profile → Contribution settings → check **Private contributions**.
(<https://github.com/settings/profile>)

## 3. Verify the snake will actually see private work

Before trusting the graph, check what the API returns for your token. Run this
with the PAT from step 1 — the second number is the part that would be missing
without it:

```sh
GH_PAT=<paste-token>
curl -s -H "Authorization: bearer $GH_PAT" \
  -X POST -d '{"query":"{viewer{contributionsCollection{contributionCalendar{totalContributions} restrictedContributionsCount}}}"}' \
  https://api.github.com/graphql
```

- `totalContributions` — what the snake will eat.
- `restrictedContributionsCount` — contributions in repos the *viewer* can't see.

Run the same query with a token that has no `repo` scope to see the difference.
If `totalContributions` matches your profile graph and looks right, you're set.

## 4. Run them

Actions → each workflow → **Run workflow**. They then run on a schedule:
snake every 6h, languages daily at 03:00 UTC.

## Notes

- `plugin_languages_indepth: yes` clones every repo and runs linguist over the
  commits that are yours. That is what makes forks meaningful — without it a
  fork credits you with the entire upstream codebase. It is also the slow part;
  if the job starts timing out, drop `repositories: 200` or turn indepth off.
- The snake writes to an `output` branch. That branch is created by the first
  successful run; the README images 404 until then.
